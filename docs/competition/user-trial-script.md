# 真实用户试用体验脚本（赛题维度 7：用户认可度）

> 用途：发给至少 2 名真实目标用户（1 名教师 + 1-2 名学生），收集结构化试用记录。
> 赛题要求：标注身份（如"XX 专业教师、XX 年级 XX 专业学生"）、使用频次、使用时间、具体场景下的实际效果。
> 系统侧已就绪：对话内点赞/点踩+纠错反馈（落 `data/feedback.jsonl`）、`/stats` 进度页、`/learning/diagnosis/summary` 诊断端点。

## 一、试用前准备（组织方）

1. 部署可访问的系统（Demo 地址或本机 `scripts/start-stage3.ps1`），确认 `.env` 已配置模型 Key。
2. 为每位用户分配独立的 `X-User-Id`（建议：教师 `teacher-<姓名缩写>`，学生 `student-<姓名缩写>`），保证学情数据按人隔离。
3. 预热知识库（`data/books/` 教材已入库）与一份示例作业文本（供批改环节使用）。
4. 记录每位用户的开始时间。

## 二、体验主线（约 20 分钟，五步闭环）

| 步骤 | 操作（用户视角输入） | 预期效果 | 记录点 |
|---|---|---|---|
| 1 智能备课 | "帮我准备《反向传播》的教案，对象是本科二年级" | 工作流自动执行四步，产出可下载 `教案-*.docx`，全程无审批打断 | 耗时、教案结构完整度主观评分（1-5） |
| 2 课件生成 | "为这个课题做一份教学 PPT" | PPT 工作流自动产出 ≥10 页 `课件-*.pptx`，可打开、有标题与要点 | 页数、内容贴合度评分 |
| 3 作业批改 | 上传示例作业附件："批改这份作业并给出改进建议" | 逐题得分+错因标签+反馈，卡片标注"建议评分，教师复核" | 评分合理性、错因是否准确 |
| 4 学情诊断 | "诊断一下我的学习情况" | 诊断报告引用聚合数据（薄弱点、正确率）；打开 `/stats` 查看薄弱点/错题归因/趋势卡 | 诊断是否可信、可视化是否直观 |
| 5 学习路径 | "根据我的薄弱点规划学习路径" | 结构化路径（阶段/知识点/资源/检验点），路径记录回显于 `/stats` | 路径可执行性评分 |

补充自由探索 5-10 分钟：鼓励用户提一个自己专业内的真实问题（知识问答场景），并对任意回答点赞/点踩。

## 三、反馈收集（试用后立即完成）

1. 系统内反馈：统计该用户 `X-User-Id` 下的点赞/点踩条数（`data/feedback.jsonl` 按 session 可查）。
2. 结构化访谈五问（记录原话）：
   - 哪个功能对你最有用？为什么？
   - 哪一步的结果需要人工修正？修正量大吗？
   - 相比手动完成同样任务，估计节省了多少时间？
   - 界面与对话流程是否顺畅？卡点在哪？
   - 是否愿意在真实教学/学习中继续使用？
3. 试用后运行一次 `/stats` 与诊断端点，截图存档（作为"系统记录与用户反馈互相印证"的证据）。

## 四、写入《06—效果验证报告》的要素清单

每位用户一节，必须包含：
- 身份标注：专业/年级/角色（教师或学生）；
- 使用频次与时间：试用日期、时长、会话数（系统 `/stats/overview` 可出数）；
- 场景与效果：上表五步的逐项记录 + 访谈原话摘录；
- 对比数据：手动备课/批改的估计耗时 vs 系统耗时（用户提供基线）；
- 截图：教案下载、PPT 产物、批改卡、诊断卡、路径卡各一张。

## 五、规模化加分项（尽力而为）

若能在班级/课程群扩散：统计独立 `X-User-Id` 数量、总会话数、反馈条数，用 `/stats/overview`（教师视角聚合）与 `feedback.jsonl` 行数出数，写入报告"规模化使用"一节。50 人以上可获额外加分（赛题原文），不足 50 人也如实呈报。
