# 阶段三 冲刺任务清单：API 桥接层 + 前端 UI（骨架版）

> 更新时间：2026-08-02（拆分为骨架 / 细节两份清单）
> 范围：`docs/TASK_BREAKDOWN_v2.md` 阶段三的**骨架部分**
> 目标：只搭建 API 层与前端层的**可运行骨架**——一条命令启动双端、完整聊天
> 闭环、多 Agent 角色可见、待审批可处理。本清单自成一体，执行时不需要阅读
> 或等待任何其他任务清单。

## 骨架与细节的边界

- **骨架 = 结构正确 + 端到端可运行 + 质量门禁绿**。不追求视觉打磨、实时
  流式、完备交互与性能优化。
- 任务中标注「→ 细节清单」的内容**一律不做**，做了视为超范围。
- 细节清单（`docs/TASKS_STAGE_3_DETAILS.md`）**由执行本清单的 agent 在收尾
  时产出**（W1-T8），本文档「明确不做」一节是其起点大纲；细节清单由另一个
  agent 执行，本清单 agent 不执行细节任务。
- 骨架的契约字段、目录约定、组件结构即为细节清单的施工框架，设计时请为
  细节预留扩展点（可选字段、可替换组件），但不要提前实现细节。

## 后端前置现状（执行前必读）

`backend/src/core/` 当前可用的公共接口，这就是本清单的全部后端依赖：

- `CollaborativeAgentGraph`：`run(user_input, session_id, user_id)` 同步执行
  一轮协作、`resume()` 恢复待审批执行、`get_state` / `get_history` 读取持久化
  状态、`get_node_info` 获取各 Agent 角色与 Prompt。
- `SessionStore`：会话元数据的创建、列表、归档。
- 状态字段：`messages` / `events`（带递增 sequence 的运行事件）/ `run_error` /
  `pending_handoff`（人机审批请求）/ `task_plan` / `task_results` /
  `current_agent`。
- 已知限制：ReAct 节点是同步调用，**不支持 Token 级流式输出**。骨架采用
  同步请求-响应；流式推送属于细节清单。

## 注意事项（与后端演进解耦）

- `core/` 可能由其他开发任务并行演进。本清单只依赖上面列出的公共接口与
  字段；若发现接口发生破坏性变化，停止相关任务、记录冲突点并汇报，
  **不擅自修改 core 来适配**。
- core 后续会新增能力（引用溯源、评价结论等）。契约中的可选字段为此预留，
  UI 必须能在字段缺失时降级渲染；接入新字段是细节清单的工作。不允许为等待
  后端新能力而阻塞本清单任何任务。
- 提交边界：本清单的提交只允许涉及 `backend/src/api/`、`frontend/`、根目录
  启动脚本与本文档，避免与其他后端开发的提交交织。

## 执行规则（开发 agent 必读）

1. 按 Sprint 顺序推进；一次只领取一个原子任务，完成后立即勾选本文档对应项。
   **骨架清单不同步勾选总清单**——总清单阶段三各项由细节清单完成后统一勾选。
2. 每个任务的完成定义 = 实现完成 + 验收标准全部通过 + 质量门禁通过。
3. 调研、大批量代码阅读等场景鼓励使用子代理，主上下文只保留结论；
   W0-T7 是强制性要求，其余自行判断。
4. 质量门禁：
   - 后端（`backend/` 目录，venv 内）：`PYTHONPATH=src .venv/Scripts/python.exe -m pytest -q`、
     `.venv/Scripts/ruff.exe check src tests`、`.venv/Scripts/python.exe -m mypy src`，
     三者在已有基线之上不允许退化。
   - 前端（`frontend/` 目录）：`npm run lint`、`npm run typecheck`、
     `npm run build` 全部通过。
5. 架构红线：
   - API 层放在新包 `backend/src/api/`，**不得修改 `core/` 现有逻辑**（纯新增
     适配代码除外）；`core` 的同步阻塞调用（graph.run 等）必须放到工作线程
     执行，不得阻塞 FastAPI 事件循环。
   - API 的请求/响应全部用 Pydantic Schema 定义，字段命名与 core 状态字段
     对齐；前端只消费由 OpenAPI 生成的类型，不手写重复定义。
   - 错误响应对外只暴露稳定错误码与脱敏信息，与 core 的错误分类风格一致。
6. 每个原子任务一次独立提交，Conventional Commits 风格；遇到阻塞记录原因并
   停止该任务，不自行扩大范围。

## 技术选型（定案，不再变更）

- 后端：FastAPI + Uvicorn；骨架只做同步 REST，SSE 流式留给细节清单（前端
  代码结构需预留接入空间）。
- 前端：Next.js（App Router）+ TypeScript strict + Tailwind CSS + shadcn/ui，
  react-markdown 渲染回答，zustand 管理客户端状态。
- 类型同步：FastAPI 自动生成 OpenAPI → `openapi-typescript` 生成 TS 类型。
- 认证：本期用 `X-User-Id` 请求头标识用户（缺省匿名，对齐 core 的
  `user_id=None` 语义）。
